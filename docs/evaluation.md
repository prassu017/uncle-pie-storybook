# Quality and evaluation

## What "good" means here

A bedtime story for ages 5 to 10 that:

- keeps every idea the family asked for, in their order
- is easy to follow aloud: short sentences, everyday words, past tense, some dialogue
- holds together: nothing happens twice, nothing appears from nowhere
- has gentle peril that resolves, and a calm ending
- shows its lesson through what the characters do

## How it is measured

Each draft is scored by the judge (see [prompting.md](prompting.md)) and by code:

| Check | Source | Blocks a pass |
|---|---|---|
| Every requested idea present (quote-verified) | Ida + code | Yes |
| Sentence length (16 words max) | Code | Yes |
| Page length (45-120 words) | Code | Yes |
| Narration slipping out of past tense | Code | Yes |
| The same scene told on two pages | Code | Yes |
| An event that already happened on an earlier page (story ledger) | Extraction + code | Yes |
| A character who appears from nowhere ("the kitten" with no introduction) | Extraction + code | Yes |
| Unsuitable words, leaked prompt text, copied plan text | Code | Yes |
| Refrain said more than once on a page | Code | Yes |
| Rubric: age fit, comfort, arc, fidelity, heart, read-aloud, moral | Vishnu | Each must be 4+ |
| Repeated events, double arrivals, unexplained objects (quote-verified) | Two continuity reads + code | Yes when both reads agree; otherwise a note |
| Stock phrases, named feelings, reading grade | Code | Note |

Continuity is read twice, independently. A problem blocks only when both reads flag the same page: a
single read raises enough false alarms that blocking on every finding made revisions oscillate.

## Samples

[`samples/`](../samples/) holds real, unedited output generated by
[`tools/make_samples.py`](../tools/make_samples.py), each with the judge's rounds. Each sample is the
better of two runs, chosen by code (passed review, then fewest problems found by the checks, then
reading level):

| Sample | What it shows |
|---|---|
| `1_assignment_example` | The example request from the original brief |
| `2_one_word_topic` | A one-word request ("dinosaurs"): the plot is invented, not demanded |
| `3_parent_request` | A parent's specific need (fear of thunderstorms, a breathing trick) |
| `4_unsafe_request_reframed` | "A knight kills a dragon", retold gently |
| `5_change_request` | A change request applied to sample 1 |

## Measured timings

Bear-and-fox story, five pages, all three outputs:

| Output | Ready at |
|---|---|
| Text | 40 s |
| Narration | 47 s |
| All illustrations | 119 s |

Text takes 35 to 90 s depending on how many review rounds a story needs. Narration and pictures run in
parallel once the text is ready; the book opens immediately.

## Design experiments

- **Whole story in one call vs. one page per call.** Writing all pages in one call originally swapped
  who rescued whom and dropped requested ideas. With per-page "new event" bookkeeping, both approaches
  were compared on the same three requests; neither was clearly better, so page-by-page is the default
  and `WRITER_MODE=whole` remains available.
- **Art-editor model.** Calibrated on a known-good and a known-bad illustration; `gpt-4.1-mini` judged both
  correctly and consistently, where a smaller vision model rejected the correct picture.

## What the checks still miss

The checks catch the mechanical failures reliably (length, tense, unsafe words, leaked prompt text,
requested ideas that never happen). Story logic is harder: gpt-3.5-turbo reads for continuity
inconsistently, so a problem blocks only when two independent reads agree, and some slip through. In the
samples and test runs these got past the judge:

- an event repeated in different enough words that the ledger doesn't match it
- an object (rather than a character) used before it was introduced
- an event repeated with a twist (a gem handed over on two consecutive pages)
- a change like "make Bob funnier" applied too lightly to notice

The story ledger was added to catch the most common of these (a scene happening twice, a character from
nowhere); on known-bad stories it catches them, with no false alarms on the samples.

## Known limitations

- gpt-3.5-turbo sets the ceiling on prose: stories are safe, faithful and coherent, but not literary.
- A change request that adds something is placed on one page and verified; a request that changes the
  whole plot ("make it about pirates instead") is applied page by page rather than re-planned from scratch.
- The judge's rubric scores cluster high; the measured checks and quote-verified reads do most of the
  discriminating.
- After the read-aloud pass, stories read at about grade 3 to 5.5, still above the grade 2-3 target on
  some pages. Reading level is not a gate, because making it blocking meant almost no story could pass.

## Roadmap

1. An evaluation set of 30 varied requests run on every prompt change, tracking pass rate, fidelity,
   reading grade and art-check pass rate.
2. Re-plan and repaint only the scenes a change request touches.
3. Read-along highlighting using word timestamps from the narration.
